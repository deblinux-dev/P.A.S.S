# Архитектура P.A.S.S.

## 1. Общая схема

```
            ┌────────────────────────────────────────────────────────┐
            │                    приложение                          │
            └───────┬───────────────────────────────┬────────────────┘
                    │ обычный код                   │ cpuid/xgetbv
                    ▼                               ▼
   ┌────────────────────────────────┐   ┌──────────────────────────┐
   │  кодовый кэш DynamoRIO         │   │  CPUID-витрина           │
   │  (трансляция через app2app)    │   │  (profile ∪ emulated)    │
   │                                │   └──────────────────────────┘
   │  BB: для каждой instr:         │
   │   opc_supported(profile)?      │
   │    ├─ да  → passthrough        │
   │    ├─ VEX-механика → inline    │
   │    ├─ special      → inline    │
   │    ├─ generic      → clean call│
   │    └─ нет          → оставить, │
   │                      поймает   │
   │                      trap      │
   └───────────────┬────────────────┘
                    ▼
            ┌───────────────┐
            │  CPU (старый) │
            └───────────────┘
```

Три уровня подмены, по возрастанию цены:

1. **Passthrough** — инструкция исполняется нативно в кодовом кэше
   (накладные расходы — только сам DR, ~10–30 %);
2. **Inline-эмуляция** — 2–15 инструкций из SSE2/SSSE3/GPR-набора;
3. **Generic clean-call** — спил контекста в per-thread BUF, вызов
   C-функции-исполнителя, восстановление (~100 нс, зависит от опкода).

## 2. Инвариант shadow-файла (эмуляция YMM без AVX)

На CPU без AVX регистров ymm физически нет. P.A.S.S. моделирует их так:

```
логический ymm_r = xmm_r (аппаратный, младшие 128 бит)
                 ∥ RAW_YHI(r) (16 байт в клиентском TLS, старшие 128 бит)
```

Правила поддержания инварианта:

| Событие | Действие |
|---|---|
| legacy-SSE запись в `xmm_r` | ничего (старшие биты сохраняются — как на реальном AVX) |
| VEX.128 запись в `xmm_r` | `RAW_YHI(r) = 0` (4×`mov dword [gs:off], 0`, без регистров) |
| VEX.256 операция | старшие половины читаются из `RAW_YHI`, результат пишется обратно |
| `vzeroupper` | все 16 `RAW_YHI` обнуляются (64 mov-imm) |
| `vzeroall` | то же + обнуление аппаратных xmm (через pxor-xmm15) |
| `vpmovmskb/vmovmskps/pd` c ymm | lo через нативную SSE2-форму, hi из shadow, `or` со сдвигом |

Благодаря тому, что обнуление YHI выполняется **безусловно** для каждой
VEX.128-записи, не требуется сброс кодового кэша при «ленивой активации»
shadow-режима.

Служебные слоты RAW TLS (адресуются `gs:disp`, помечаются мета):

| Слот | Назначение |
|---|---|
| `RAW_YHI(0..15)` | старшие половины ymm |
| `RAW_T0/T1` | staging mem-операндов (выравнивание legacy-SSE) |
| `RAW_S15` | спил xmm15 (универсальный scratch) |
| `RAW_TG/TG2` | спилы временных GPR |
| `RAW_TG3` | образ eflags для «безшумных» для флагов эмуляций |

Важно: обращения к клиентскому TLS из вставляемых инструкций **обязаны**
помечаться мета (`instr_set_meta`), иначе DR манглит `gs:` как сегмент
приложения (база = 0) и запись уходит по нулевому адресу.

## 3. Generic-путь (clean call)

Для «сложных» опкодов на этапе трансляции генерируется:

```
mov  [gs:RAW_SV10], r10          ; спил носителя
mov  r10, [drmgr TLS]            ; r10 = per-thread BUF
pushf ; pop [r10+BUF_FLAGS]      ; захват флагов-источников (если нужны)
movups [r10+BUF_XMM(k)], xmmk    ; спил исходных/результирующих xmm
mov  [r10+BUF_GPR(k)], gprk      ; спил GPR (rax — всегда: носитель флагов)
call emu_generic                 ; clean call, fpstate=true
movups xmmk, [r10+BUF_XMM(k)]    ; перезагрузка результатов
mov  gprk, [r10+BUF_GPR(k)]
push/popf                        ; флаги-результаты (если определяет)
mov  rax, [r10+BUF_GPR(0)]       ; rax — всегда последним
mov  r10, [gs:RAW_SV10]          ; восстановление носителя
```

C-исполнители (`emu.c`) работают с образами регистров как с массивами и
компилируются без использования SIMD-состояния приложения
(`fpstate=true` у clean call страхует xmm/x87). Память приложения читается
через `opnd_compute_address` по спилу GPR — сегментные базы учитываются DR.

## 4. CPUID-витрина

`exposed = (host ∩ profile) ∪ (emulated ∧ expose_emulated)`; при экспозиции
AVX автоматически добавляются XSAVE/OSXSAVE, лист 0xD передаётся от хоста
(с выставленным битом AVX-состояния), AVX-512-биты всегда глушатся.
`xgetbv` подменяется на константу `0x3 | (AVX? 0x4)`.

Следствие: `ifunc`-диспетчеры glibc и `__builtin_cpu_*`-ветки выбирают
именно те пути, которые P.A.S.S. умеет исполнить. Динамическую glibc,
собранную под x86-64-v3, это не спасает — проверка ISA-уровня выполняется
до нашей витрины полезной нагрузки (см. ограничения).

## 5. Trap-fallback

`drmgr_register_signal_event(SIGILL)`: декодирование по `raw_mcontext.pc`,
если опкод не поддерживается профилем — эмуляция на месте через тот же
`emu.c` (образ регистров из mcontext, shadow из RAW TLS), `pc += length`,
`DR_SIGNAL_REDIRECT`. Если эмуляции нет — `DR_SIGNAL_DELIVER`: приложение
падает так же, как на настоящем Core 2. Windows (v0.1): только диагностика
через `drmgr_register_exception_event`.

## 6. Методика отладки (как локализовались ошибки)

Серия дефектов v0.1 и их признаки — полезно для будущих доработок:

1. **`translation field must be set`** — вставленные app-инструкции без
   translation-полей. Решение: sentinel-метка вокруг зоны вставки +
   проставление `instr_set_translation` всем вставленным.
2. **Сегфолт по адресу `0x2a0`** — `gs:`-операнд в немета-инструкции:
   DR манглит сегмент приложения. Решение: авто-мета в `pass_ins` для
   инструкций с клиентским TLS и без app-памяти.
3. **`no encoding found: movups xmm → ymm`** — смешение ширин: любое
   смешение XMM/YMM в создаваемых инструкциях запрещено; рабочий регистр
   256-битных путей — младший xmm приёмника; индексы из YMM-имён
   нормализуются (`xmm_idx` принимает YMM).
4. **`no encoding found: mov m64, imm32` / `mov xmm → m16 через OP_mov`** —
   использовать `movups` для xmm и 4×dword imm для обнулений.
5. **Порча rax** — перезагрузка флагов через rax затирала приложение-rax:
   rax спилится всегда и восстанавливается всегда последним.
6. **`bzhi`+`jne` в strncmp** — флаги от sub/xor вместо флагов bzhi:
   флаги-результаты восстанавливаются из образа.
7. **`pop [gs:mem]`** — манглинг pop-with-memory в DR использует rsp как
   scratch и конфликтует с сегментным манглингом: только `pop reg`.
8. **`lea [idx-1]` c 32-битным dst** — DR не кодирует: заменять на
   `sub 1` + `and/xor` через TG-спил.
9. **GPR-ширины**: DR кодирует EAX и RAX разными enum — все проверки и
   спилы нормализуются `reg_resize_to_opsz(r, OPSZ_8)`.
10. **vpmovmskb/vmovmskps с ymm** — читают ВЕСЬ регистр; если оставить
    нативными, читают мусор из hardware-hi. Обязательна эмуляция
    (lo|hi<<16) с сохранением флагов (оригинал их не трогает).
11. **vzeroupper** — должен обнулять shadow, иначе последующие split-пути
    читают устаревшие старшие половины.

Диагностические рубильники `-no256/-no128/-nospecial/-nobcast/-nomsk/-novz`,
`-nospoof`, `-emu_mask <hex>` позволяют бисецировать пути; `-verbose 3`
печатает каждую вставленную последовательность, `-verbose 4` — трассировку
значений, `-verbose 1` — app-PC при SIGSEGV/SIGABRT (символизация через
objdump/nm), SIGABRT-проб помогает ловить abort() в glibc.

## 7. Открытые проблемы v0.2

1. **Редкий layout-зависимый крах под pass** (воспроизводится только в
   selftest, ~1 из N запусков, зависит от раскладки кодового кэша).
   Кандидаты: пустая последовательность при удалении no-op
   `vmovdqa ymm,ymm`; интеракция staging-слотов T0/T1/T2 в соседних BB.
   Методика: маркеры прогресса + `-verbose 3` + бисекция `-emu_mask`.
2. Bun под `core2` — вероятно, починен вместе с багами §6.12+;
   требуется перепроверка.
3. FMA — двойное округление (mul→add); точный режим — v0.3.

## 8. Журнал дефектов v0.2 (как чинился «стартап glibc»)

Открытая проблема v0.1 (§7.1 — SIGSEGV на старте статической glibc 2.41,
зависание динамической) закрыта. Корневые причины — десять, все
систематические (методика: бисекция по `-nospoof` → `-emu_mask` →
последовательности в `-verbose 3` → изолированный asm-тест → дифф-хеш):

1. **rewrite_256 не удалял исходную инструкцию** (`instrlist_remove` был
   только в rewrite_128): на хосте с AVX оригинал исполнялся нативно
   поверх эмуляции; 256-битные store писали в память мусор из аппаратной
   старшей половины. — «тихий» краш старта.
2. **vmovdqa/vmovdqu/vmovss/vmovsd отсутствовали в vex-карте** — уходили
   в default (`return 1` = passthrough) и исполнялись нативно: на целевом
   CPU — SIGILL, который trap считал «легальным», а 256-битные store
   портили память. Добавлены в карту; default теперь отдаёт generic-опкоды
   на эмуляцию и отсекает EVEX явно.
3. **Спил носителя r10 в generic-пути лежал в RAW_YHI(0)** — порча тени
   ymm0 (RAW_SV10=456; RAW_SIZE расширена).
4. **LZCNT/TZCNT inline через BSR/BSF**: (а) src==dst затирал источник
   константой (`tzcnt eax,eax` → ctz(32)=5 — strlen в __strlen_avx2);
   (б) LZCNT(0) давал ~(width-1) вместо width; (в) флаги не определены.
   Переведены на generic-путь с точными значениями и флагами.
5. **Инвертированный PF** в flags_arith (влиял на BZHI и др.): чётность
   считалась наоборот.
6. **PF у LZCNT/TZCNT** — реальные CPU не выставляют чётность; для
   неотличимости от натива PF держится нулём (наблюдение на серверном CPU).
7. **PEXT/PDEP: DR-IR хранит операнды как [маска, данные]** — эмулятор
   читал наоборот → результат бит-сдвинут. Найдено дифф-хешем selftest.
8. **Алиасинг dst==src в VEX.256-арифметике** (`vpcmpeqb ymm2,ymm1,ymm2`,
   `vsqrtps ymm2,ymm2` …): staging старшей половины затирал младшую xmm
   приёмника до сравнения → маска «сам с собой». Введён staging
   перекрытых половин в RAW_T0/T1/T2.
9. **vpmovmskb с dst==rax**: результат затирался загрузкой образа флагов
   в rax-носитель (путь __strlen_avx2_rtm). Результат сохраняется в TG2.
10. **Лист 0xD отдавался прозрачно с хоста** при подменённом XCR0=0x7 —
    рассинхрон XCR0↔leaf D (AVX-512/PT-состояния) ломал xsave-инициализацию
    glibc. Лист D теперь согласован с витриной (576/832 байта).
11. **vmovq/vmovd XMM↔GPR** — кодировщик DR 11.9x segv-ится на легаси-форме
    (disasm ок, encode — крах). Обход: маршрутизация через xmm15/staging
    (доказанные паттерны).
12. **Счётчик g_stat_static** не инкрементировался; статистика врала.

Регрессионная сетка: 8 asm-юнитов + 4 побайтных диффа (printf-батарея,
строковая батарея, матрица LZCNT/TZCNT с флагами, KAT-selftest) +
статические приложения (memset/strlen-only, hello, stress) — все зелёные
под полным профилем core2 на хосте с AVX-512; динамические бинари работают.
